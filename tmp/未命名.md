renderer迎来第一次抽象。
我正在将render-scheduler从模型A迁入到模型B，render-scheduler.submit在when_all时render task需要往secondary cmd写入命令，但是目前的vulkan_renderer不支持这个操作，原因是还需要传入一个索引参数才能让render task知道究竟该用secondary cmd buffers中的哪个buffer。
所以这算是目前renderer的抽象程度不够，renderer应该分为1. 提供vulkan环境的部分；2. 提供帧绘制的环境。
现在的vulkan_renderer是vulkan环境 + 帧环境 x N。
但对于一个render task来说，它只依赖vulkan环境+帧环境。
所以我希望将renderer抽象成concept，用vulkan做实现。
伪代码：
```cpp
concept global-env-renderer = requires
{
	{ r.instance(); }  -> convertible_to<VKxxx const&>;
	{ r.xxx(); } -> convertible_to<VKxxx const&>;
	...
}
concept frame-env-renderer = requires
{
	{ r.primary cmd(); }  -> convertible_to<VKxxx const&>;
	{ r.secondary cmd(); }  -> convertible_to<VKxxx const&>;
	...
}
concept renderer = global && frame -env-renderer;

```
可以添加forward实现来增加灵活性：
```cpp
struct global-env-vulakn-renderer 
{ 
	_instance;
	auto instance() return _instance;
	...
};
struct forward-global-env-vulkan-renderer
{
	global-env-renderer* _inner_renderer
	auto instance() return _inner_renderer.instance();
}
```
转发层的存在可以让renderer的传递变得极其轻量（可以直接传值），也可以增加灵活度，某个地方有特殊实现可以直接继承forward。
