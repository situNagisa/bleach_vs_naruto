# 核心规则

以下规则是 `modern-cpp-coding-standard` 的默认规范。用户要求和明确的项目 profile 优先于它们。

## 语言版本与现代习语

- 使用当前编译器和目标支持的最新标准。优先使用该标准提供的语言和标准库设施，而不是旧写法。
- 工具链提供 contracts 时使用 contracts；没有时用 `assert` 作为 contracts 违规的后备实现。
- 在选定标准和工具链支持时，积极使用静态反射、`::std::execution`、`::std::println` 和 coroutine，并在它们能改善设计时优先采用。
- 优先使用 ranges/views、CTAD、指定初始化、结构化绑定、带初始化语句的 `if`/`for`、`using enum`、concepts 和 `requires`。

## 命名

- 宏使用全大写 snake_case（`REGISTER_WIDGET`）。
- 模板形参使用大驼峰（`Value`、`Allocator`）。
- 其他名称一律使用小写 snake_case。不使用匈牙利命名、类型前缀或成员后缀。ECS、GPU、RNG 等有明确含义的行业缩写可以保留，其他词不要缩写。

## 命名空间与函数调用

- 引用其他根命名空间中的名称时，从全局命名空间开始限定（`::std::vector`、`::boost::...`）。
- 明确每个非成员函数调用的查找意图。只有在有意使用且确实需要 ADL 时才保持非限定调用；定向调用库函数或项目函数时，使用其命名空间限定。
- `using namespace` 只允许出现在函数体内。命名空间别名在 `.cpp` 顶层使用时应确实能提高可读性。

## 布局与文件

- 使用 Tab 缩进。根据可读性决定换行和行长，不设置硬性的列数上限。
- 使用常规空格（`if (x)`、`a + b`、`foo(a, b)`、`a : b`）；函数之间和逻辑段之间空一行。
- 命名空间内部的声明不缩进。
- 按功能或模块聚合文件。默认使用 `.h`/`.cpp` 和 `#pragma once`，除非项目 profile 规定其他布局。
- Include 顺序为：标准库、第三方库、跨模块项目头文件、本模块头文件；组间空行，组内除非项目要求不要排序。

## 类型、声明与初始化

- 使用东 `const`（`int const&`）。声明变量时同时初始化，不留下未初始化对象。只有确实需要未初始化存储时，才使用当前标准支持的 indeterminate 设施。
- 激进使用 `auto`：初始化表达式已经表达类型时使用 `auto`。不要写冗余的声明符（例如 `auto*`）；借用引用且需要保留表达式引用类别时使用 `auto&&`。如果显式类型能表达重要契约或避免有意义的转换，则使用显式类型。
- 能在编译期计算时标记 `constexpr`/`consteval`。不抛异常的函数标记 `noexcept`。
- 无意引入隐式转换时加 `explicit`；语义明确且有意的隐式转换可以保留。
- 忽略返回值很可能是错误时加 `[[nodiscard]]`。
- 默认使用成员公开的 `struct`。成员变量在语义上默认为私有：保持访问修饰为 `public`，但使用单下划线加小写名称（例如 `_value`）表示不属于对外使用者的接口。禁止 `_X`、`__x` 等触发实现或标准保留规则的标识符；不要使用可能与编译器或标准库冲突的名称。这里的“私有”是面向设计角色和使用者的可见性语义，不是机械地隐藏所有成员：根据成员服务的对象（外部使用者、外层类型或内部实现）决定其公开程度。若项目 profile 需要真正的访问控制，遵循 profile。
- 使用 `enum class`、语义匹配的整数类型和 C++ 风格转换，禁止 C 风格转换。
- 类的构造函数能保持平凡时就保持平凡；其他特殊成员也应在不影响语义时保持平凡，不要声明没有语义作用的成员函数。能表达所有权且允许 RVO 时按值传参与返回；不要仅为触发 RVO 在返回表达式中添加 `std::move`。指针表示可空关系，引用表示非空关系，值表示接收所有权的 sink。

## 所有权与错误处理

- 有生命周期的资源使用只移动 RAII 所有者：构造时获取，析构时释放；清理检查放在所有者内部，不要在每个调用点重复处理。
- 动态 I/O 和其他可预期的运行时失败使用异常。禁止抛出 `::std::logic_error`；逻辑错误使用 contracts 或 `assert`。
- 无法安全恢复的错误使用 `::std::terminate`。
- Contracts/assertions 表达前置条件、后置条件和不变式。不能用静默跳过非法操作的分支来替代它们。

## 模板、迭代与注释

- 使用 concepts 和 `requires`，不用 SFINAE 或 `enable_if`。
- 迭代时优先使用 ranges/views，前提是它们能清楚表达所有权和求值时机。
- 公共行为的文档要求由项目 profile 决定。实现内注释说明“为什么”，不要描述代码已经显而易见的“做了什么”。
