# 现代 C++ 编码规范

所有 C++ 任务都适用本 skill，包括实现、重构、API 设计和代码审查。核心规则优先采用编译器和构建配置允许的最新 C++ 能力。项目 profile 可以在核心规则上增加限制和项目决策。

## 确定实际生效的规范

修改代码前，先检查仓库中的 `AGENTS.md`、构建文件、编译器选项、`.clang-format` 和编码文档。确定当前编译器和目标实际支持的最高语言标准；项目没有明确说明时，默认使用该标准。读取仓库提供的项目 profile 并应用其中的限制。

冲突按以下顺序处理：

1. 用户明确提出的要求。
2. 项目文档和本地指令。
3. 项目 profile。
4. 本 skill 的核心规则。
5. 一般 C++ 建议。

不要为了满足本 skill 而引入包装层、兼容层、工具链变更或无关的大范围格式化。项目已有明确约定时保持其一致性；如果它与核心规则冲突且会影响当前改动，说明该冲突。

## 核心规则

实现或审查代码时读取 [references/core-rules.md](references/core-rules.md)。该文件包含命名、格式、命名空间、初始化、所有权、错误处理、模板和现代语言设施的规范默认值。

## 项目 profile

Profile 用于增加限制和记录项目决策，不用于放宽核心默认值。它可以规定语言和工具链上限、格式、API 可见性、文档、错误传递、ABI、模块、并发或框架约束。仓库提供 profile 时优先使用；没有 profile 时，只根据项目证据推断限制。[references/profile-template.md](references/profile-template.md) 提供了精简的 profile 结构。

## 编写与审查

编写代码时直接应用实际生效的规范，保持改动内部一致。优先完成范围明确的小改动，避免机械式重写。

审查代码时使用以下分类：

- **规范要求**：违反生效的核心规则或项目限制。
- **建议改进**：没有项目规则强制，但可以提高一致性或质量。
- **项目特例**：只有在发现对应项目 profile 或架构依据时才成立。

每个规范要求都指出具体规则并给出集中、可执行的修正。不要因为配置的工具链不支持某个更新设施而报告问题。
