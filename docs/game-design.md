## 1. 一句话定义

一个**从零用原生 C++ 自研引擎**打造的、**2.5D 二次元风格的在线 5v5 英雄 MOBA**：斜俯视视角、固定英雄阵容、技能驱动战斗、三线带野区、完整经济系统（小兵 / 打野 / 金币 / 局内升级 / 出装），单局 8~15 分钟，推塔摧毁敌方基地获胜。

定位：**长期个人作品集项目**。真正的看点不止游戏本身，而是背后那套**自研引擎 + 渲染抽象 + 网络同步**。

---

## 🎯 核心设计哲学（贯穿全局）：用 MOBA 成长表达番剧强度，而非格斗分阶

角色定位（坦 / 输出 / 辅）只是大方向，**角色设计极其灵活**。灵感是"死神 vs 火影"式的番剧群像格斗，但用 **MOBA 的等级 + 装备 + 节奏**给它深度（而非传统 2D 格斗那种单一）：

- **差异化的基础属性模板**：不同角色可以有本质不同的属性机制——比如剑八天生高护甲、抗揍又能爆发，而非"数值高一点的坦克"。
- **差异化的强度曲线**：成长型角色（一护、鸣人）靠等级 / 装备体现"前期弱、后期强"的成长弧；番剧里本就很强的角色可设计成"前期强、后期乏力"。
- **以曲线平衡，而非分阶**：不靠传统格斗"为公平给角色分等级 / 限定形态"（否则蓝染打初始一护必然暴打），而是用成长节奏让强弱随时间自然流动——**每个角色都有自己的强势窗口**，公平来自"你有你的时代、我有我的时代"。
- **技术含义**：需要一套**高度数据驱动、允许逐角色改写规则（属性 / 减伤 / 资源 / 被动）的角色系统**——"角色 = 数据 + 可插拔效果 / 规则"，而非写死的类。

## 4. 关键设计影响与注意点

1. **2 朝向精灵 + 技能型 MOBA 的"瞄准可读性"问题**：角色只有左右两面，玩家不易从立绘看出技能朝向。**对策**：所有技能 / 普攻都配**地面瞄准指示器（telegraph）**，施法时在地面画出弹道 / 范围。M2 即纳入。

2. **"完整经济 + 三线 + 5v5 + 自研引擎 + 单人 + 弹性时间"是独立开发的极限组合**。可行的唯一方式是**里程碑切得极小、每步都能独立运行 / 展示**。**建议第一可玩版本先用 1 条路验证**，跑通后再扩成 3 路。

3. **手感与控制（A 层已锁定）**——这是个 **键盘优先的"动作 MOBA"**：
   - **控制**：WASD 移动 + JKLUIOP 技能 + 鼠标仅辅助，**必须能纯键盘玩**。
   - **瞄准模型（混合）**：指向类技能朝"朝向 / 移动方向"发射 + 地面指示器；指定类 / 普攻用**软锁定**（最近 / 可切换目标）；自身 / 范围技能以自己为中心；鼠标可选精修。
   - **普攻（弱化）**：保留普攻但不强调；补刀更宽松（如范围内击杀即计入金币），降低精度门槛、贴合键盘动作流。
   - **战斗节奏**：中长 TTK，偏策略，宽容网络延迟；数值做成可调参数。
   - **镜头**：固定斜俯角 + 跟随 + 可小幅拉动。
   - **视野**：先全图可见，**架构预留**按队伍裁剪可见性（战争迷雾 / 草丛后期再加）。
   - **输入层**：抽象成"移动向量 / 瞄准 / 技能触发"，不写死按键（手柄暂不做，但低成本预留）。
   - **连带影响**：键盘输入流天然适合未来 lockstep；与"2 朝向精灵"契合。

4. **英雄与技能框架（B 层已锁定）**：
   - **职能**：三大定位 坦克 / 输出 / 辅助（输出再分近战 / 远程）。
   - **技能槽**：少而深的**连招 / 派生**式 —— J/K/L 核心招式（带派生）、U 大招、I/O/P 通用键（闪避 / 装备主动 / 回城）。
   - **连招机制工具箱**：连段序列 + 蓄力长按 + 命中·状态·格挡派生（**不做**方向派生，WASD 仅用于走位 / 瞄准）。
   - **资源**：CD + 蓝条，蓝作为"连招预算"（偏宽松，限制无限连而非"没蓝就废"）。
   - **MVP 英雄数**：3 个（一坦一输出一辅助），长线目标 12+。
   - **味道参照**：格斗 / 动作连招博弈 × MOBA 推塔经济。

## 5. 技术架构

### 5.1 总原则

原生 C++；**第三方库一律藏在自己的接口背后**，保证可替换、不污染设计；**渲染 / 计算后端可切换**（Vulkan → CUDA）；**仿真层与渲染 / 输入彻底解耦**（后期能上联网、上 CUDA、做无头服务器的命根子）。

### 5.2 分层架构（依赖只能向下）

```
┌─────────────────────────────────────────────┐
│  Game（MOBA 规则）：英雄/技能/经济/AI/胜负      │
├─────────────────────────────────────────────┤
│  Simulation（确定性友好·定步长·可无头运行）       │ ← 联网与 CUDA 计算都挂这层
│     单位/ECS(数据导向)/物理/寻路                 │
├──────────────────────┬──────────────────────┤
│  Networking           │  Presentation         │
│  (传输接口·ENet 起步)  │  渲染/动画/特效/相机/UI/音频 │
├──────────────────────┴──────────────────────┤
│  GPU 抽象：RHI(图形) + Compute(计算) 两个后端    │ ← Vulkan 现在 / CUDA 以后
├─────────────────────────────────────────────┤
│  Platform（窗口/输入/计时/文件） + 资源 I/O       │
└─────────────────────────────────────────────┘
```

**关键铁律**：`Simulation` 绝不依赖 `Presentation` / `RHI`。这样它才能在服务器上无头、确定性地运行。几乎不增加前期成本，却保住所有后路。

### 5.3 渲染与计算后端

- **现在**：Vulkan 图形后端；游戏计算（物理 / 寻路 / 粒子）跑在 CPU。
- **抽象层**：`IRenderBackend`（图形）+ `IComputeBackend`（计算）两个接口。
- **以后**：接 CUDA 实现这两个后端，用 **CUDA-Vulkan interop** 共享缓冲 / 图像。
- ⚠️ CUDA 是 N 卡独占，故为"可选加速路径"，**Vulkan 永远是可移植基线**，按硬件择优。
- 💡 单位数据用**数据导向 / SoA（结构体数组）**布局——既缓存友好，又天然适合上传 GPU 做 CUDA 计算，正好服务"大量小兵野怪 + 后期 CUDA"目标。仿真层建议用轻量 ECS。

### 5.4 网络（选定"先能联机就行"）

- **起步**：一台 peer 当 host 跑权威仿真，其他客户端发输入、host 广播状态快照，客户端做插值。先 LAN 两人，再扩 5v5。用 ENet 藏在 `INetTransport` 后。
- 快照模型不要求严格确定性，起步轻松。
- 但因仿真层从 M0 起就解耦 + 定步长，未来升级到**确定性帧同步（lockstep）**或**专用权威服务器 + 预测**时，门都开着。

### 5.5 推荐第三方库（每个都藏在自己接口后，可随时换）

| 用途 | 推荐 | 备注 |
|---|---|---|
| 构建 | CMake | 跨平台友好（比 .vcxproj 更利于扩平台） |
| 窗口/输入/音频 | SDL3 | 一站式、可移植；藏在 Platform 后 |
| Vulkan 脚手架 | volk + VMA + vk-bootstrap | 减少初始化样板 |
| 数学 | glm | 以后若上 lockstep 可换定点数 |
| 调试 UI | Dear ImGui | 自研引擎的命根工具，建议早集成 |
| 网络传输 | ENet | 简单可靠 UDP，契合"先能联机" |
| 图片/字体 | stb_image / stb_truetype | 单头文件 |
| 模型(以后) | cgltf（glTF） | 3D 场景用 |
| 单测 | doctest / Catch2 | 给确定性仿真写回归测试 |

### 5.6 角色系统与内容管线

- **英雄 = C++ 动态库插件**：每个英雄编译成独立动态库（DLL），通过稳定的**插件 API** 接入游戏核心；可**热重载**、支持**第三方 / modding**。插件 API/ABI 的边界设计是这套架构的核心难点（明确"宿主向英雄暴露什么"：仿真状态访问、效果系统、事件钩子、版本化）。
- **三层内容模型**：C++ 插件（独特逻辑）+ 数据表（属性 / 数值，可热重载、用于平衡）+ Lua（配置 / 轻量 glue）。对应"角色 = 数据 + 可插拔规则"的哲学。
- **2D 精灵动画系统**：精灵表解析 + 由战斗 / 连招状态驱动的动画状态机，渲染为 3D 场景中的 billboard（2 朝向、左右翻转）。直接吃《死神 vs 火影》素材。
- **工具链（早投入）**：ImGui 内置面板 + 数据 / 脚本 / 插件**热重载**，改英雄和数值即时生效——对"大量英雄 + 按曲线平衡"是迭代效率的命根。

## 6. 里程碑路线图（按里程碑切，不按时间——契合"时间弹性"）

每个里程碑都是**能独立运行 / 展示**的成果。

- **M0 · 地基**：CMake 工程 + 分层骨架（空接口）+ SDL3 窗口 + Vulkan 画三角形 / 贴图四边形 + **定步长主循环（仿真 tick 与渲染解耦）** + ImGui。
- **M1 · 一个能动的英雄**：3D 场景 + 斜俯视跟随相机 + 2D billboard 角色（左右翻转 + 占位动画）+ 移动控制。
- **M2 · 战斗系统**：血量 / 伤害 / 死亡复活 + 数据驱动技能系统 + **地面瞄准指示器** + 普攻。
- **M3 · MOBA 生态（先 1 路）**：小兵成波推线 + 防御塔 + 野怪 + **完整经济** + 寻路。
- **M4 · 完整单机一局**：扩成三线 + 野区 + 摧毁基地胜负 + 3~5 占位英雄 + bot AI 凑满 5v5 + HUD/小地图/计分板。**← 第一个真正惊艳的里程碑。**
- **M5 · 联网 MVP**：`INetTransport` + ENet；host 权威 + 快照 + 插值；先 1v1/LAN，再扩 5v5；房间 / 匹配（bot 补位）。
- **M6 · Netcode 加固**：快照增量压缩、插值 / 延迟补偿、重连、**无头服务器构建**，可选转 lockstep。
- **M7 · CUDA 后端（可选加速）**：在计算 / 渲染接口后实现 CUDA（粒子 / 大量单位 / 寻路 + 渲染 interop），与 CPU/Vulkan 对比基准。
- **M8 · 内容与表现**：替换真美术、定世界观 / 角色 / 更多英雄 / 装备 / 平衡、音效、菜单。

> **优先级建议**：先一路打通到 **M4**（完整人机一局）再碰联网（M5+）与 CUDA（M7）。永远有个能玩的东西，士气与风险最可控。

## 7. 主要风险

| 风险 | 对策 |
|---|---|
| MOBA 联网（确定性 + 海量单位）最难 | 仿真从 M0 起解耦 + 定步长 + 确定性友好；netcode 先简单后升级 |
| 自研引擎 + 完整 MOBA + 单人，体量巨大 | 里程碑细切、占位美术、先 1 路再 3 路、M4 前不碰联网/CUDA |
| Vulkan+CUDA 双后端拖慢前期 | CUDA 是后期实现；前期只建抽象（抽象便宜，实现延后） |
| 2 朝向精灵看不清技能朝向 | M2 起强制地面瞄准指示器 |
| 完整经济内容量大 | 英雄 / 装备先少（MVP 3~5 英雄），跑通再扩 |
